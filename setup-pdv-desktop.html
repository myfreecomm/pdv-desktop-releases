01

Visão geral

O PDV Desktop não é configurado na máquina. Quase tudo o que ele usa — tokens, loja, séries fiscais, métodos de pagamento, terminais — é cadastrado antes no Nexaas Onboarding, que envia para a nuvem do PDV (Sync.Api). No primeiro login, isso desce para o caixa. Por isso a ordem importa: cada etapa depende da anterior.

#EtapaOndeSem ela, o que acontece
1Conta e loja criadas no OMSOnboarding → coluna OMSO PDV Desktop não pode ser ativado
2Ativar a conta no PDV DesktopOnboarding → AccountsNada chega à nuvem do PDV; nenhum evento do OMS é recebido
3Conferir os webhooks (criados na ativação)Nexaas OMS → Integrações → WebhooksNada do que muda no OMS (produtos, preços, estoque, vendedores, clientes) chega ao caixa
4Criar a loja no PDV DesktopOnboarding → OrganizationsLoja fica sem promoções e sem configurações
5Configuração e métodos de pagamentoOrganization → Configuração PDV DesktopCaixa sobe sem regras de venda e sem formas de pagamento
6TerminaisOrganization → Terminais PDV Desktop"Nenhum terminal disponível para esta organização"
7VendedoresNexaas OMSNinguém consegue entrar no caixa
8Carga inicialBackfill (engenharia)Caixa abre sem produtos, preços ou clientes
9Instalação e primeiro loginMáquina da loja—

Tudo pelo Onboarding. O operador de implantação não chama a API da nuvem do PDV: os links Criar, os botões Importar do PDV Desktop / Enviar ao PDV Desktop e o Salvar fazem isso. A API direta fica para o suporte, no apêndice.

02

Antes de começar

Reúna isto antes de abrir o Onboarding. Faltar qualquer item costuma aparecer só no login do caixa, com uma mensagem que não aponta a causa.

Acesso

  • Login no Nexaas Onboarding pelo Nexaas ID
  • O domínio do seu e-mail precisa ter um grupo cadastrado no Onboarding — sem ele, o login volta para a tela inicial sem entrar
  • Permissão para editar Accounts e Organizations

Dados da loja

  • Razão social, nome fantasia, CNPJ, IE, endereço e regime tributário
  • Série da NF-e da loja (modelo 55)
  • Série da NFC-e de cada caixa (modelo 65)
  • Formas de pagamento aceitas e parcelamento
  • Cashback, se contratado: provedor e token
  • Credenciais do Agente Omnitax (contingência fiscal)

Da máquina da loja

  • Windows 64 bits (x64)
  • Usuário com permissão de administrador para instalar
  • Placa de rede física (o caixa é identificado pelo MAC)
  • Portas locais livres: 5001, 3000 e 8080
  • Internet no primeiro login (a carga inicial é online)

Onboarding de homologação ≠ de produção. Cada ambiente do Onboarding envia para a nuvem do PDV daquele ambiente. Se a integração estiver desligada, as ações respondem Integração do PDV Desktop desligada neste ambiente — é configuração do servidor, acione a engenharia.

03

Ativar a conta

Onboarding · Accounts

A ativação liga o PDV Desktop ao OMS do cliente e cadastra na integração do OMS os webhooks que passam a alimentar o caixa com produtos, preços, estoque, vendedores e clientes (seção 4).

  1. Garanta a conta e a loja no OMS

    Em Accounts e em Organizations, a coluna do OMS precisa estar concluída. A ativação usa a primeira loja da conta no OMS para ler o canal de venda e o estoque. Criar o Promo também é recomendado: sem ele, a conta sobe sem token de promoções.

  2. Clique em Criar na coluna PDV Desktop

    Na lista de Accounts, a coluna PDV Desktop mostra:

    IndicadorSignificado
    ✗ "Criar a conta no OMS primeiro"Falta a etapa anterior
    CriarPronta para ativar
    ✓Já ativada

    Sucesso responde PDV Desktop ativado no sync-api. O campo ID no PDV Desktop sync-api é preenchido sozinho com o ID da conta no OMS — não edite.

Mensagem de erroO que fazer
"Account ainda não foi criada no OMS"Criar a conta no OMS pela coluna OMS
"Nenhuma Organization da conta foi criada no OMS."Criar a loja no OMS primeiro
"Organization no OMS sem sale_channel global ou stock"Provisão do OMS incompleta — revisar canal de venda e estoque da loja

Salvar a Account não envia nada. Só o link Criar ativa. Depois de ativada, a conta é reenviada automaticamente a cada Salvar de uma Organization.

04

Webhooks no OMS

Nexaas OMS · Integrações

Os webhooks fazem o OMS avisar a nuvem do PDV a cada produto, preço, estoque, vendedor ou cliente alterado. Você não precisa criá-los: o Criar da ativação da conta (seção 3) já os cadastra na integração do OMS. Esta seção é a referência do que ele cria — para conferir e, se algum faltar ou for apagado, recriar à mão.

Onde ver

No OMS, selecione a conta do cliente no topo e abra Integrações (engrenagem) → Webhooks. Os quatro devem aparecer com status Disponível.

Recriar à mão (só se necessário)

  1. Clique em Criar webhook (ou em Editar, se ele existir mas estiver incompleto).

  2. Preencha o Nome e a URL do ambiente conforme a ficha abaixo. O token de autorização fica em branco.

  3. Marque exatamente os recursos e eventos da ficha e salve.

Conferir

Não duplique. Antes de criar, confira se o webhook já não existe com o mesmo propósito. Duas cópias fazem o OMS mandar cada evento em dobro para o caixa.

05

Criar a loja

Onboarding · Organizations

Com a conta ativada, cada loja que vai usar o PDV Desktop precisa ser criada nele. CNPJ, IE e endereço descem do OMS a cada login do caixa; o que vai para a nuvem do PDV são as configurações de integração.

  1. Preencha os campos que o Desktop usa

    O Onboarding marca no próprio rótulo para onde cada campo vai: (Omni, Desktop) ou (Desktop). Campo sem marca é só do PDV Omni (mobile).

    CampoBlocoDestino
    Série NFE (NF-e, mod. 55)Dados tributáriosOmni, Desktop — obrigatória
    Cadastro do cliente obrigatórioPDV ConfiguraçãoOmni, Desktop
    Impressão automática de NFC-ePDV ConfiguraçãoOmni, Desktop
    Nexaas Provedor de Cashback / Token cashbackPDV ConfiguraçãoOmni, Desktop
    Nexaas Cashback Company UUID (CRMBonus)PDV ConfiguraçãoDesktop
    Cone Agent - Terminal Agent ID / TokenPDV ConfiguraçãoDesktop (Agente Omnitax)

    Série NFCE do bloco "Dados tributários" não vale para o Desktop. No Desktop a série da NFC-e é por caixa e é cadastrada no terminal (seção 7). O campo da loja é do Omni.

  2. Salve e clique em Criar na coluna PDV Desktop

    Na lista de Organizations: ✗ "Ativar a conta no PDV Desktop primeiro", ✗ "Criar a organização no OMS primeiro", ou Criar. Sucesso responde Organização criada no PDV Desktop (sync-api).

Campos compartilhados mudam os dois PDVs. Cadastro do cliente obrigatório e impressão automática de NFC-e têm cadastro único: ao salvar, valem para o PDV Omni e para o Desktop ao mesmo tempo. Na configuração do Desktop eles aparecem só para conferência.

Mudou a série da NF-e depois? O caixa só lê a série no login: peça para o operador sair (Del) e entrar de novo.

06

Configuração e pagamentos

Onboarding · Organization

Na mesma tela da Organization, o bloco Configuração PDV Desktop define como o caixa se comporta. É o que o operador vê depois em Configurações (F8).

  1. Loja que já opera? Importe antes

    Se a loja já tinha configuração na nuvem do PDV, clique em Importar do PDV Desktop antes de editar. O Onboarding bloqueia o envio de uma configuração que nunca foi importada, para não apagar a que está em uso ("…o cadastro local nunca foi importado…"). Loja nova pode pular este passo.

  2. Preencha a configuração

    BlocoO que definir
    GeralTema · Ambiente fiscal (padrão Homologação) · ID de promoções Nexaas
    VendasExigir vendedor no início · vendas em aberto · estoque negativo · validar estoque antes do pagamento · converter em retirada · finalizar venda automaticamente
    Regras e permissõesQuais ações pedem senha gerencial (entrada e sangria, trocar vendedor, fechar caixa de outro usuário) · e-mail de fechamento · atualizar clientes · troca pelo mesmo valor · abrir caixa com o saldo do último fechamento
    PagamentoPagamento na retirada · valor mínimo da parcela · máximo de parcelas (padrão 1) · taxas por parcela

    Todas as opções começam desligadas. O efeito de cada uma no balcão está no Manual do PDV, seção 13.

  3. Ative os métodos de pagamento

    A configuração nasce com 8 métodos, todos inativos, um por aba: PIX, Link de Pagamento, Cartão de Débito, Cartão de Crédito, Vale, Dinheiro, Pagamento na Retirada e Pagamento Externo. Em cada aba, marque Ativo nos que a loja aceita e, no crédito, marque Permite parcelamento e cadastre as parcelas.

    Parcela não cadastrada não existe no caixa — nem a 1x. E não crie um segundo método do mesmo tipo: o Onboarding deixa, mas o caixa de uma máquina nova não consegue concluir o vínculo do terminal.

    Link de Pagamento ainda não foi implementado no PDV Desktop. O método aparece na lista do Onboarding e pode ser ativado, mas ainda não funciona no caixa. Mantenha-o inativo até a liberação.

  4. Salve

    O Salvar envia a configuração geral, a de pagamento e os métodos. A tela confirma com Enviado ao PDV Desktop — config geral: atualizada; … ou avisa Falhou ao enviar … ao PDV Desktop. Uma falha não desfaz o que foi salvo no Onboarding: corrija e salve de novo.

07

Cadastrar os terminais

Onboarding · Organization

Um terminal por caixa físico, no bloco Terminais PDV Desktop da Organization. O terminal nasce livre e é "reivindicado" pela máquina no primeiro login, que grava nele o próprio MAC.

  1. Adicione uma linha por caixa

    ColunaRegra
    NomeObrigatório — ex.: "Caixa 01"
    Número do caixaOpcional
    SérieSérie da NFC-e (mod. 65) deste caixa. O Onboarding aceita em branco, mas o caixa não

  2. Clique em Enviar ao PDV Desktop

    Salvar não envia terminais — só este botão, no topo da Organization. Ele também reenvia configuração e métodos, e para no primeiro erro ("Enviado antes da falha: …"). Terminal enviado ganha um ID no PDV Desktop.

Terminal sem Série não aparece para o operador. A tela de vínculo do caixa só lista terminais livres e com série. Esquecer esse campo é a causa mais comum de "Nenhum terminal disponível para esta organização".

Acompanhar e liberar

  • Em uso e Dispositivo (o MAC) só se atualizam com Importar do PDV Desktop; "?" significa que nunca foi consultado.
  • Liberar desvincula o terminal da máquina ("Terminal … liberado no PDV Desktop."). Use ao trocar o computador de um caixa.
  • Remover só aparece em terminal ainda não enviado. Terminal já enviado não pode ser excluído — a nuvem do PDV não tem exclusão; renomeie ou deixe sem uso.

Não confunda com os terminais do Omni. A mesma página tem os blocos Terminals e Payment configurations, que são do PDV Omni (mobile). O do Desktop é Terminais PDV Desktop.

08

Vendedores e acesso

Nexaas OMS

Os usuários do PDV Desktop são os vendedores do OMS — o Onboarding não cadastra usuário do Desktop. Eles chegam ao caixa pelo webhook PDV Desktop Geral, criado na ativação da conta. Login e senha são os mesmos do OMS.

No cadastro do vendedor (OMS)Efeito no PDV
Acesso ao PDV ligadoSem ele, a loja aparece como Sem acesso
Status ativoInativo também vira Sem acesso
Loja que o vendedor atua no PDVÉ esta loja que libera o login. Vínculo administrativo com outras lojas não conta
GerenteO e-mail e a senha dele passam a valer como senha gerencial no caixa

Senha gerencial não é uma senha separada. É o login de qualquer vendedor marcado como gerente na loja. Garanta pelo menos um gerente cadastrado antes do primeiro dia: fechar caixa de outro usuário e as ações escolhidas na seção 6 dependem dele.

Vendedor cadastrado antes da ativação da conta não gerou webhook: ele só chega ao caixa pela carga inicial (seção 9).

09

Carga inicial

Engenharia

Os webhooks trazem o que muda depois da ativação. O que já existia no OMS — catálogo, preços, vendedores, clientes, estoque — precisa ser carregado uma vez pelo backfill. Sem ele, o caixa abre vazio.

  • A nuvem do PDV dispara a carga sozinha quando a conta é criada pela primeira vez na ativação. Se a conta já existia lá (reativação), a carga não é disparada.
  • O disparo é "melhor esforço": se a fila não estiver configurada no servidor, ele só registra um aviso no log.
  • O Onboarding não mostra o andamento da carga. Confirme com a engenharia antes de marcar a instalação — o disparo manual está no apêndice.

Planeje o tempo. A carga é processada em fila única. Clientes entram a cerca de 2 por segundo: uma base de 16 mil leva por volta de 2 horas. Ative a conta no dia anterior à instalação, não com a equipe da loja esperando.

10

Instalar na máquina

Loja

Existem dois instaladores, um por ambiente. Eles não se misturam: cada um tem seu nome, sua pasta de dados e seu canal de atualização, e os dois podem conviver na mesma máquina.

HomologaçãoProdução
AplicativoNexaas PDV HMLNexaas PDV
InstaladorPDV-Desktop-HML-<versão>.exePDV-Desktop-<versão>.exe
VersãoX.Y.Z-beta.NX.Y.Z
Dados locais%APPDATA%\Nexaas\PDV-HML%APPDATA%\Nexaas\PDV
Logs%LOCALAPPDATA%\Nexaas\PDV-HML\logs%LOCALAPPDATA%\Nexaas\PDV\logs

  1. Execute o instalador como administrador

    A instalação é para a máquina toda e pede elevação. O instalador não é assinado digitalmente, então o Windows mostra o aviso de Editor desconhecido do SmartScreen: clique em Mais informações → Executar mesmo assim.

  2. Decida sobre o Agente fiscal

    Uma página própria oferece Instalar o Agente Omnitax neste terminal (recomendado), já marcada. O agente é o que emite NFC-e em contingência quando a internet da loja cai; marcado, o instalador também instala o Java 8.

    Desmarcar é reversível só reinstalando. Sem o agente, o caixa só emite nota com internet. Máquinas instaladas antes desta opção existir também precisam de reinstalação com a caixa marcada.

  3. Peça as exclusões do antivírus à TI do cliente

    O agente fiscal ainda não tem reputação no Windows Defender e pode ser bloqueado sem mensagem nenhuma. Solicite exclusões para:

    • C:\Program Files\Omnitax\Agent
    • a pasta de instalação do PDV

  4. Abra o aplicativo

    A tela Inicializando sistema... sobe o serviço local e para em 99% até ele responder — isso é normal. Se o serviço não responder em 30 segundos, o aplicativo fecha sozinho (ver seção 14).

Atualizações. O PDV verifica versão nova ao abrir o login e ao fim da sincronização. A tela Nova atualização disponível oferece Baixar atualização ou Sair — atualizar não é obrigatório, e a atualização mantém a escolha do agente fiscal.

11

Primeiro login

PDV Desktop

Quatro telas, uma única vez por máquina. É aqui que tudo o que foi cadastrado nas seções anteriores desce para o caixa.

  1. Acesse sua conta

    E-mail e Senha do vendedor (as do OMS) → Acessar. Use um vendedor com acesso ao PDV na loja que está sendo instalada — de preferência o gerente.

  2. Selecione a sua loja

    As lojas aparecem nas abas Homologação e Produção conforme o oms_base_url da conta. Se o usuário tem uma loja só, esta tela é pulada.

    "Sua máquina ficará vinculada apenas a esta loja". Depois do primeiro login, trocar de loja exige apagar o banco local (seção 15). Confirme a loja antes de clicar.

  3. Vincule a um terminal

    Escolha o caixa entre os terminais livres; cada um mostra a Série da NFC-e. Se esta máquina já tinha um terminal, o PDV o reconhece pelo MAC e pula a lista.

  4. Autorize o Agente fiscal

    Se o agente foi mantido no instalador, o Windows pede uma confirmação de administrador (UAC) logo após o vínculo. Aceite: recusada, ela volta no próximo login e a loja fica sem contingência até lá.

  5. Espere a sincronização

    Sincronizando seus dados... mostra o progresso de Produtos, Clientes e Configurações. Não feche o aplicativo. Terminada, o PDV vai para a tela Início.

Os logins seguintes são diretos. A máquina já sabe a loja e o terminal, e o login passa a funcionar também offline para quem já entrou nela uma vez. A cada login com internet, o PDV confere se o terminal continua vinculado a esta máquina.

12

Depois do login

Antes de liberar o caixa para a equipe, feche o ciclo: periféricos, uma venda de teste e a nota.

  1. Configure os periféricos

    Configurações (F8) → Periféricos: impressora térmica (vem como Nenhuma), impressora A4 se a loja emite DANFE, e TEF e Pin Pad — código da empresa, servidor (local ou IP) e dispositivo.

  2. Confira os dados da loja

    Em Configurações → Geral, os dados da organização (CNPJ, IE, endereço, séries NF-e e NFC-e) vêm do OMS e do Onboarding. Divergência aqui se corrige lá, não no caixa.

  3. Abra o caixa e faça uma venda de teste

    Abrir caixa com o valor da gaveta, venda um item, pague e confirme que a NFC-e sai autorizada e imprime. Teste também um cartão, se a loja usa TEF.

Checklist final

Nuvem

  • Conta e loja criadas no OMS (e no Promo)
  • Conta com ✓ na coluna PDV Desktop
  • 4 webhooks PDV Desktop (Products, Geral, Prices, Stock) no OMS, Disponível, sem duplicados
  • Loja com ✓ na coluna PDV Desktop e Série NFE preenchida
  • Configuração PDV Desktop salva sem mensagem de falha
  • Métodos aceitos ativos, um por tipo, crédito com parcelas
  • Um terminal por caixa, todos com Série, enviados ao PDV Desktop
  • Carga inicial concluída (produtos, preços, clientes)
  • Vendedores com acesso ao PDV e pelo menos um gerente

Máquina

  • Instalador do ambiente certo
  • Agente fiscal instalado e UAC aceito
  • Exclusões do antivírus aplicadas
  • Loja e terminal certos vinculados
  • Sincronização concluída
  • Impressora e TEF configurados
  • Venda de teste com NFC-e autorizada

"Seu cadastro não possui acesso a nenhuma loja…" Vendedor sem acesso ao PDV, inativo ou sem senha Cadastro do vendedor no OMS (seção 8)
Loja marcada Sem acesso Mesma causa, para aquela loja Cadastro do vendedor no OMS

Erro genérico ao entrar ("An error occurred during sign-in") Token ou URL do OMS inválidos na conta da nuvem do PDV Reativar a conta (seção 3); persistindo, engenharia
"Nenhum terminal disponível para esta organização" Terminal não enviado ao PDV Desktop, sem Série, ou todos em uso Seção 7; Liberar no terminal preso

Produto, preço ou estoque alterado no OMS não chega ao caixa Webhook ausente, indisponível, com URL de outro ambiente ou sem o evento Seção 4
Vendedor novo não consegue entrar Webhook PDV Desktop Geral ausente ou sem os eventos de seller Seção 4

Pin Pad não encontrado Arquivos do TEF ausentes no pacote instalado Acionar engenharia (problema de build)
15

Trocar loja ou terminal

Trocar o terminal (mesma loja)

Libere o terminal atual na nuvem no Onboarding (Liberar, seção 7). No próximo login com internet, o PDV percebe que perdeu o vínculo e volta para a tela de terminais.

Trocar a loja

Não há opção no aplicativo. Feche o PDV e apague local.db (e os arquivos -wal e -shm) da pasta de dados do ambiente. No próximo início ele recria o banco e refaz o primeiro login.

Trocar o computador

Clique em Liberar no terminal (Onboarding) e faça o primeiro login na máquina nova. O terminal é reconhecido pelo MAC, não pelo banco local.

Apagar o banco local apaga o que ainda não subiu. Antes, feche o caixa e confirme em Vendas realizadas que não há Venda não sincronizada. O banco também é por usuário do Windows: entrar com outro usuário do Windows começa do zero.

Apêndice: API da nuvem

Suporte · Engenharia

Para diagnóstico e correções que o Onboarding não cobre. Todas as rotas exigem Authorization: Bearer <chave da API> do ambiente. Rotas PUT substituem o registro inteiro: leia antes, reenvie todos os campos.

ParaRota
Ver o que o caixa recebe da lojaGET /organizations/{id} (já com a herança da conta)
Listar terminaisGET /terminals?accountId=&organizationId=
Liberar terminalPUT /terminals/{id}/release
Ver configuraçõesGET /configurations/general/{orgId} · /payment/{orgId} · /payment-methods?organizationId=
Refazer cargaPOST /accounts/{id}/backfill?only=prices (sempre forçada)

Carga pelo Backfill.Orchestrator

dotnet run -- --accountId 87                 # respeita o checkpoint
dotnet run -- --accountId 87 --force         # recarrega tudo
dotnet run -- --accountId 87 --only sellers --force
dotnet run -- --accountId 87 --only customers --force --organizationId 415

Entidades de only: brands, categories, features, products, skus, prices, sellers, customers, stocks. Restringir por loja só funciona pelo Orchestrator.

Duas armadilhas da API. Na conta, o canal de venda se chama oms_sale_chanel_id (com erro de digitação — a grafia correta é ignorada em silêncio). E o ambiente da conta (aba Homologação/Produção no login) vem do oms_base_url: contém "hml" ou "homologation" → Homologação.
